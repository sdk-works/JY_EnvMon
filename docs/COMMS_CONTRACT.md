# 京阳温室 JY_EnvMon ↔ 云端 通信契约（v1.2）

> 固定监测终端（JY_EnvMon）与云端（smart-greenhouse-cloud）通信基准。
> 未定稿前不实现固件代码。云端与模拟器可在契约定稿后先行开工。
> v1.2：boot_id 改为独立双元数据扇区、数据轮换代次/迁移完成标识、补传调度规则确定化、uptime_ms 用 uint64、光照用 uint32。
> 生效日期：2026-10-17。

## 1. 链路总览

```
棚内传感器
   │ RS485
JY_EnvMon (STM32F407): 采集 → 校验 → 缓存(内部Flash双扇区) → 组JSON → 发送
   │ RS232 (USART1, 9600 8N1)
DR154 (有人): 4G 联网、MQTT 透传
   │ MQTT
云端 Broker(EMQX) → FastAPI → PostgreSQL(落库) → 返回业务ACK
```

- MCU 承担：采样有效性、报文标识(msg_id)、Flash 缓存、应用层重试。
- DTU(DR154) 承担：蜂窝联网与 MQTT 传输。**首期由配置工具预配置，MCU 不发 AT 指令。**
- 业务确认以**落库 ACK** 为准；MQTT 收到 ≠ 云端入库。

## 2. Topic 约定

| 方向 | Topic | QoS | retained |
|---|---|---|---|
| 设备上报 | `agri/device/{device_id}/up` | 1 | 否 |
| 设备确认 | `agri/device/{device_id}/ack` | 1 | **否** |

- `device_id`：固件身份标识，与云端 `Device.device_id` 一致。
- **Topic 中的 device_id 必须与报文 body 的 device_id 一致**；不一致的报文拒绝。
- **大棚归属由云端设备绑定决定，不信任 payload 自报的 greenhouse_id**（可作冗余字段，不用于鉴权/归属）。
- 禁止把 ACK 与配置混在同一 Topic。订阅/发布权限只覆盖本设备允许的主题（Broker ACL）。

## 3. 上行遥测报文（设备 → 云端）

Topic: `agri/device/{device_id}/up`
MQTT 负载：**单行 JSON**（结尾 `\n`，见 §8.4 打包）。

```json
{
  "type": "telemetry",
  "schema_version": 1,
  "device_id": "JY001",
  "msg_id": "JY001/17/42",
  "boot_id": 17,
  "seq": 42,
  "sampled_at": 0,
  "time_quality": 0,
  "uptime_ms": 259200000,
  "data": {
    "temperature": 21.5,
    "humidity": 54.5,
    "co2": 603,
    "light": 1375,
    "pressure": 101.6,
    "soil_temperature": 20.6,
    "soil_moisture": 45.0,
    "soil_ec": 1200.0,
    "valid": [1,1,1,1,1,1,1,1]
  }
}
```

### 3.1 字段语义

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 固定 `telemetry` |
| `schema_version` | int | 契约版本，本版 = 1 |
| `device_id` | string | 设备身份，与 Topic 一致 |
| `msg_id` | string | 全链路唯一，见 §4 |
| `boot_id` | int | 启动编号，跨重启递增（持久化） |
| `seq` | int | 本次启动内序号，从 1 递增 |
| `sampled_at` | number | 采样时间（秒）。无可信 RTC 填 0，见 §5 |
| `time_quality` | int | 0=无可信时间；1=有可信时间 |
| `uptime_ms` | number | **采样时刻**运行时长（ms，uint64 语义），见 §5 |
| `data.*` | number 或 null | 8 个测量值，见 §3.2 |
| `data.valid` | array[8] | 对应 8 个量是否有效（1/0），顺序固定 |

### 3.2 数据顺序（与 valid 对应，与显示轮播顺序无关）

`[0]=temperature, [1]=humidity, [2]=co2, [3]=light, [4]=pressure,
 [5]=soil_temperature, [6]=soil_moisture, [7]=soil_ec`

### 3.3 无效值（统一为 null）

- 单路失败：`data.*` 填 **`null`**，对应 `valid[i]=0`。**不填 0**（0 是合法读数，如夜间光照、CO2 为 0）。
- 全量无效：`data.*` 全 null，`valid` 全 0。表示**终端在线但采集异常**，**不判为离线**。
- 云端空值判断用 `is None`，**禁止 `a or b`**（会把合法 0 当空值丢弃）。

## 4. 消息编号 msg_id（跨重启不重复）

- 格式：`{device_id}/{boot_id}/{seq}`，如 `JY001/17/42`。
- `boot_id`：启动编号，跨重启单调递增，**独立双元数据扇区持久化**（§10.5）。**编号丢失不得自动从零开始**；只有两个元数据扇区都无效（首次上电）才从 1 开始。
- `seq`：本次启动内从 1 递增；发送后不变，**重发同一消息用同一 msg_id**。
- 目标：任何两次重启后发出的消息编号不撞车。缓存重传必须保留原 msg_id。

## 5. 时间处理（关键约束）

- **没有可信时间源时，固件不得伪造 ISO 时间戳。**
- `sampled_at`：有可信时间填秒级时间戳；无可信时间填 `0`，`time_quality=0`。
- 云端：`sampled_at=0` 且 `time_quality=0` 时，**不得绘制成 1970 年**，标为时间未知；补传历史样本按 sampled_at 画曲线，**不得把补传接收时间当采样时间**。
- `uptime_ms`：必须指**采样时刻**的运行时长。
  - **使用 uint64 语义**（JSON 里按 number 传输，值 < 2^64）。
  - **运行时长回绕与"是否有可信绝对时间"是两回事**：是否可信由 `time_quality` 表达；uptime_ms 自身始终如实上报（uint64 在设备生命周期内不会回绕，除非运行 >584 年，可忽略）。
- 云端：入库时记录 `received_at`（服务器接收时间）。

## 6. 传感器失效处理

- 见 §3.3：失败量填 `null` + `valid[i]=0`，不传旧值/零值。
- 全失败：仍上报，`valid` 全 0，云端按"在线但采集异常"处理，不判离线。

## 7. ACK 协议（云端 → 设备）

Topic: `agri/device/{device_id}/ack`
负载（单行 JSON，`\n` 结尾，retained=否）：

```json
{ "type": "upload_ack", "msg_id": "JY001/17/42", "status": "stored" }
```

- **云端完成数据库事务提交后**才发送；**数据库失败时绝不发送成功 ACK**。
- 去重：数据库唯一约束 `(device_id, msg_id)`。
  - 重复上报：只保存一条，**仍返回 stored 成功确认**。
  - **同一编号携带不同内容：记录冲突，不能直接确认成功**（返回冲突/拒绝，不存数据）。
- **固件规则：只有收到匹配 `msg_id` 且 `status=stored` 的 ACK，才标记该条已确认。**
- 发送成功、重试次数到、超时 —— 都不能代替业务确认来删缓存。
- 永久格式错误的消息：单独标记/记录，不阻塞后续数据。

## 8. 发送、补传与重试策略（固件，规则确定化）

### 8.1 实时采样与生成
- **每 60 秒生成并持久化一条新记录**（含最新采样 + 有效标志），写入 Flash 缓存队列。

### 8.2 发送槽调度（确定规则）
- 发送槽间隔**至少 5 秒**（每次发送占一个槽，重试也占槽）。
- 每个发送槽的处理：
  1. 若存在**尚未发送的新记录**，且距离上次发送新记录已 ≥60s，则发送一条最新数据；
  2. 否则补发历史缓存（按序，保留原 msg_id/sampled_at）；
  3. 每发送 **3 条历史**，若存在尚未发送的新记录，**优先发送一条新记录**；否则继续补历史。
- **插队不额外生成样本**（只是调度优先级，不改变 60s 的采样节律）。
- 效果：消化积压的同时，不让实时数据被长期饿死；不会因"每 3 条插最新"把采样频率提高到 20s 一次。

### 8.3 重试与恢复
- 未确认消息：指数退避重发（5s→10s→20s→40s…上限 300s），重试占用发送槽。
- 连续 N 次（如 5 次）无 ACK 判定链路故障，**停止密集重发，保留周期探测**（如每 30s 发一条最新数据/心跳试探）。
- 链路恢复（收到任一条 ACK）后立即进入补传模式。
- **不得"失败 N 次后永久停发"**——必须保留周期探测，否则可能永远停发。

### 8.4 打包
- 一次串口发送不一定对应一条 MQTT 消息（DR154 可能分包/粘包）：接收端须按 `\n` 正确组帧（LineFramer）。

## 9. 单位约定（与传感器协议核验后生效）

| 量 | 单位 | 换算 |
|---|---|---|
| temperature / soil_temperature | ℃ | 寄存器÷10，负值按厂家 int16 解释 |
| humidity / soil_moisture | %RH / % | 湿度÷10；含水率按型号协议核验 |
| co2 | ppm | 原值 |
| light | lux | 32 位寄存器（高字×65536+低字），按 uint32 保存 |
| pressure | kPa | ÷10（是否÷10须依据正式传感器协议确认） |
| soil_ec | µS/cm | 按型号协议核验（勿与 mS/cm 混用） |

> 光照：固件存储用 **uint32** 完整保留无符号寄存器值；JSON 上报按实际 lux 数值。具体允许范围待传感器协议确认后补。

## 10. Flash 缓存设计（内部 Flash，双扇区轮换）

**目标**：每 60s 一条、可缓存 24h（1440 条）。硬件：STM32F407VET6，512KB。

### 10.1 扇区分配（RM0090 核实）

| 区域 | 扇区 | 地址 | 大小 | 用途 |
|---|---|---|---|---|
| 程序区 | Sector 0-3 | 0x08000000 ~ 0x0800FFFF | 64KB | 程序（.sct 限制，不与缓存重叠） |
| 数据区A | Sector 5 | 0x08020000 ~ 0x0803FFFF | 128KB | 遥测缓存（轮换） |
| 数据区B | Sector 6 | 0x08040000 ~ 0x0805FFFF | 128KB | 遥测缓存（轮换） |
| 元数据1 | Sector 4 | 0x08010000 ~ 0x0801FFFF | 64KB | boot_id/代次 持久化 |
| 元数据2 | Sector 7 | 0x08060000 ~ 0x0807FFFF | 128KB | boot_id/代次 持久化（独立扇区） |

> 元数据使用 **两个独立擦除扇区（Sector 4 与 Sector 7）**，可各自擦除、互为备份，跨擦除掉电安全。避免此前"同一扇区双槽位"的缺陷。

### 10.2 容量核算（扣除头部与预留）

| 项 | 值 |
|---|---|
| 单条记录 | 64B（见 §10.3） |
| 1440 条(24h) | 92KB |
| 单数据扇区原始 | 128KB → 理论 2048 条 |
| **实际可用（扣扇区头 + 预留）** | **约 2000 条 ≈ 33h**（够 24h，按保守值计） |
| 双数据扇区 | Sector5 + Sector6 轮换，掉电安全 |

> 容量以扣除扇区头、代次/迁移元数据后的**保守可用值（约 2000 条）**为准，不把 2048 理论值当可用容量。

### 10.3 单条记录格式（64B，小端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4 | boot_id | uint32 |
| 4 | 4 | seq | uint32 |
| 8 | 4 | sampled_at | uint32 秒；无 RTC=0 |
| 12 | 8 | uptime_ms | **uint64**，采样时刻运行时长 |
| 20 | 1 | time_quality | 0/1 |
| 21 | 1 | valid 位图 | 8 bit |
| 22 | 32 | data[8] | 8×4B；**光照用 uint32，其余 int32** 定点，见 §10.6 |
| 54 | 1 | 已确认标志 | 0xFF=待发，某位写0=已确认 |
| 55 | 1 | 提交标识 | 0xFF=未完成，0x00=已写入完成 |
| 56 | 2 | CRC16 | 覆盖偏移 0~55（不变部分） |
| 58~63 | 6 | 保留/对齐 | 0xFF 填充 |

### 10.4 状态位写入方向（关键约束）

- **Flash 编程只能把 1 写为 0，不能把 0 写回 1。**
- 状态：待发 = `0xFF`；收到 ACK 后已确认标志**某一位写 0**（只 1→0）。
- CRC **只覆盖不变数据区（0~55）**，不含可变状态字节，改状态不破坏原 CRC。
- 提交标识：写完数据区+CRC 后**最后**把提交标识从 `0xFF` 写 `0x00`，作为"该条完整写入"标记。重启扫描：提交标识非 `0x00` 视为残缺，丢弃。
- 出队回收：靠批量迁移回收，不逐条擦除。

### 10.5 掉电安全：数据双扇区轮换 + 独立元数据扇区

**数据区 A/B 轮换（Sector5/6）**
- 定义**扇区代次**（persist，存元数据扇区），每次完整迁移 +1。
- **整扇区迁移完成标识**：写满当前扇区时，先把保留数据复制到备用扇区并校验完整（逐条 CRC + 总数核对），**再写迁移完成标识**，最后擦旧扇区。复制/确认期间掉电，旧扇区未擦仍完整。
- **重启选择规则**：选代次最新且迁移完整的扇区。**仅逐条 CRC 正确不能证明所有保留记录已复制完**——必须校验记录总数与迁移完成标识。
- 禁止"先擦旧扇区再重写"。

**元数据（boot_id/代次，Sector4 + Sector7 双独立扇区）**
- 每个扇区内**追加写**启动编号/代次记录（每条带 CRC + 提交标识），写满后再迁移。
- 新编号**提交并校验成功后**，才允许生成本次启动的消息。
- 迁移完成后才擦旧扇区。
- **编号丢失时不得自动从零开始**：只有两个元数据扇区都无效（首次上电）才从 1 开始；任一扇区有有效编号则沿用并续写。

### 10.6 定点编码（data[8]）

| 索引 | 量 | 存储 | 定点（存值 = 实际值 × 倍率） |
|---|---|---|---|
| 0 | temperature | int32 | ×10 |
| 1 | humidity | int32 | ×10 |
| 2 | co2 | int32 | ×1 |
| 3 | light | **uint32** | ×1（完整保留无符号寄存器值） |
| 4 | pressure | int32 | ×10 |
| 5 | soil_temperature | int32 | ×10 |
| 6 | soil_moisture | int32 | ×10 |
| 7 | soil_ec | int32 | ×1 |

- 固件组 JSON 时÷倍率还原；光照还原为 uint32→JSON number。
- 无效量：data[i] 填 0（存储），靠 valid 位图区分"0 值"与"无效"。

### 10.7 队列管理

- 收到 ACK：对应记录已确认标志写 0，逻辑出队。
- 空间回收：批量迁移回收，不逐条操作。
- 队列满策略：**丢弃最旧未确认记录并计数**，不覆盖已确认/最新数据；丢弃数在状态页可见。

## 11. 看门狗（IWDG）

- 使能 IWDG（如 4s 超时）。
- **喂狗必须在主循环确认一轮正常推进后执行，不得在定时中断里无条件喂狗。**
- 阻塞操作（Modbus 轮询、Flash 擦写）须控制最坏耗时，不能超过看门狗窗口。

## 12. DR154 配置要求（现场预配置，MCU 不承担 AT）

- 服务器地址/端口、设备凭据、发布 `agri/device/{device_id}/up`、订阅 `agri/device/{device_id}/ack`。
- 串口：9600、8、N、1。
- TLS/证书验证：**须实测当前固件是否支持**，不支持则用非 TLS 端口并评估风险。
- 打包行为：实测 DR154 是否按 `\n` 切分 MQTT 消息；若不分包，云端按 `\n` 组帧（LineFramer）。
